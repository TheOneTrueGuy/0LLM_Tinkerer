## Minimal Integration Plan: circuit-tracer

### 1. Clone and Install circuit-tracer
- Clone the [circuit-tracer repo](https://github.com/safety-research/circuit-tracer).
- From the cloned directory, run:  
  `pip install .`
- Ensure dependencies don't conflict with your current environment.

### 2. Add a Simple Gradio UI Element
- In your Gradio app, add a section (tab, button, or panel) for "Circuit Tracing."
- Provide a text input for the prompt and a dropdown for model/transcoder set (e.g., "gemma", "llama", or custom config path).

### 3. Backend: Run circuit-tracer Attribution
- When the user submits a prompt, use Python's subprocess module to call the circuit-tracer CLI with the appropriate arguments (prompt, transcoder set, slug, graph_file_dir, etc.).
- Save the output files to a known directory.

### 4. Launch the Visualization Server
- After attribution and graph file creation, launch the circuit-tracer server (again via subprocess).
- Capture the port (default is 8041, but you may want to allow the user to specify or randomize it to avoid conflicts).

### 5. Provide a Link/Button to Open the Visualization
- In your Gradio UI, display a button or link that opens `http://localhost:8041` (or the chosen port) in the user's browser.
- Optionally, display a message/instructions about what to expect.

### 6. (Optional) Display Static Results in Gradio
- If you want, you can also parse and display some static results (e.g., summary stats, graph images) in your Gradio app, but this is not required for minimal integration.

### 7. (Optional) Clean Up
- Provide a way to stop the server from your UI, or instruct the user to close it manually.

## Weight Inversion Tinker Feature

### Concept
A "one-button tinker" feature that allows inverting model weights by multiplying them by -1. This can be applied to:
- Entire model (all weights)
- Specific layers (attention, MLP, embeddings, output)
- Specific blocks within layers
- Individual weight matrices (query, key, value, etc.)

### Mathematical Approach
- Simple multiplication: `weight *= -1`
- Preserves weight magnitudes, only flips signs
- Can be applied selectively to different components
- Reversible operation (apply twice to restore original)

#### Gradio Interface Components
- Dropdown: Inversion scope (Full Model, Attention Only, MLP Only, Output Only, Custom)
- Checkboxes: Specific layers to invert
- Slider: Layer range selection
- Button: "Invert Weights"
- Button: "Restore Original" (undo inversion)
- Status display: Show what was inverted

#### Inversion Configurations
1. **Full Model**: All parameters
2. **Attention Only**: All attention weights (Q, K, V, output projection)
3. **MLP Only**: All MLP/feed-forward weights
4. **Output Layer**: Final classification/language modeling head
5. **Embedding Layer**: Input token embeddings
6. **Custom**: User-selected specific layers/components

#### Safety Features
- **Backup**: Store original weights before inversion
- **Undo**: One-click restoration
- **Preview**: Show which parameters will be affected
- **Confirmation**: Require confirmation for full model inversion

#### Advanced Options
- **Partial Inversion**: Multiply by values other than -1 (e.g., -0.5, -2.0)
- **Random Inversion**: Randomly invert subset of weights
- **Layer-wise Analysis**: Invert one layer at a time and compare outputs
- **Progressive Inversion**: Gradually invert from output to input layers

### Expected Experimental Results
- **Full Model**: Likely nonsense output, useful for testing robustness
- **Output Only**: "Anti-model" that predicts least likely tokens
- **Attention Only**: Inverted attention patterns, different focus
- **MLP Only**: Altered reasoning/feature detection
- **Single Layers**: Identify critical layers for specific behaviors
